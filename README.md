# NO-AI

Claude Code가 쓰는 한국어 글에서 AI 슬롭을 제거하는 플러그인입니다. 설치하면 켜진 상태로 시작해서 처음에 켤 일은 없습니다. 쓰지 않으려면 `/no-ai:off` 로 끕니다.

팀 노트에 배포 소식을 쓰게 하면 이렇게 바뀝니다.

```text
고치기 전
결론부터 말하면, 이번 배포의 핵심은 **속도**입니다 — 첫 화면이 무려 두 배 빨라졌습니다!

고친 뒤
이번 배포로 첫 화면이 열리는 시간이 2초에서 1초로 줄었습니다.
```

뜸들이기, 굵게 쓰기, em dash, 과장을 빼고 숫자를 남겼습니다. 실제 글을 고친 예는 `examples` 폴더에 14개 있습니다.

## 고치는 글과 규칙

규칙은 실제로 쓴 글이 받은 지적을 모아 만들었습니다. 모든 글에 쓰는 공통 규칙과 글 종류별 규칙으로 나뉩니다.

- 공통: em dash, 가운뎃점, 굵게 쓰기, 뜸들이기와 예고, 번역투 단어, 문어체 동사, AI 상투구, 챗봇 인사와 맺음말, 말 순서 뒤집기, 문단 길이, 개수 표기, 과장, 기호와 이모지
- 글 종류별: 사내 문서, 고객에게 가는 글, 메신저, 개발 글(커밋, PR), 화면 문구, 화면 배치, 교안, 에세이, 대화 답변, 발표 자료, 지원서, 홍보 글, 번역

공개된 AI 말투 목록도 참고했습니다: [Wikipedia: Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing), [blader/humanizer](https://github.com/blader/humanizer), [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai), [mitmirsein/clear-korean-writer](https://github.com/mitmirsein/clear-korean-writer), [한국어 AI 글쓰기 상투 패턴 gist](https://gist.github.com/woonjangahn/3ad4d8fe1804aed2e7cafc9493ec566f). 이 목록 가운데 업무 글에 맞는 패턴만 한국어 규칙으로 옮겼고, 대화 기록에 돌려 정상 문장이 걸리는 검사식은 범위를 좁혔습니다.

켜져 있으면 요청마다 Claude에게 규칙 파일을 따르라는 안내가 붙습니다. 공통 규칙은 첫 문장을 안내에 함께 넣고, 자주 어기는 규칙은 따로 강조합니다. 정해진 표현으로 찾을 수 있는 규칙은 검사 도구가 다 쓴 글에서 다시 찾아냅니다.

## 준비

- Claude Code
- git
- Python 3. 터미널에서 `python --version` 을 쳤을 때 버전이 나와야 합니다.

Windows에서 Python을 새로 설치할 때는 설치 첫 화면의 "Add python.exe to PATH"를 체크합니다. Mac은 `python3` 만 있는 경우가 많습니다. 그때는 터미널에서 아래 한 줄을 실행해 `python` 으로도 불리게 합니다.

```
sudo mkdir -p /usr/local/bin
sudo ln -s "$(command -v python3)" /usr/local/bin/python
```

## 설치

3단계입니다. 1번과 2번은 한 줄씩 따로 실행하고, 앞 단계가 성공한 뒤 다음 단계로 넘어갑니다.

1. 터미널에서 마켓플레이스를 추가합니다.
   ```
   claude plugin marketplace add yehsb123/no-ai
   ```
2. 이어서 플러그인을 설치합니다.
   ```
   claude plugin install no-ai@no-ai
   ```
3. Claude Code를 닫았다가 다시 엽니다. 열 때 "NO-AI가 켜져 있습니다"가 보이면 끝입니다.

설치한 창에서는 다시 열기 전까지 규칙이 적용되지 않습니다. 다시 열지 않고 바로 쓰려면 입력창에 `/reload-plugins` 를 입력합니다.

1번과 2번은 Claude Code 입력창에서 `/plugin marketplace add yehsb123/no-ai`, `/plugin install no-ai@no-ai` 로 해도 됩니다. 두 줄을 한 번에 붙여 넣으면 한 명령으로 읽혀 설치되지 않습니다.

## 쓰는 법

따로 입력할 명령은 없습니다. 평소처럼 한국어 글을 부탁하면 됩니다. Claude가 글을 쓰기 전에 누가 읽는지, 어디에 붙여 넣는지부터 확인하고, 글의 종류에 맞는 규칙으로 쓴 뒤 검사까지 합니다.

```
이번 주 배포 내용 팀 노트로 써줘
고객사에 보낼 일정 변경 메일 초안 써줘
랜딩페이지 첫 화면 문구 다시 써줘
방금 고친 내용 커밋해줘
```

팀 노트, 고객 메일, 커밋, 화면 문구, 교안, 블로그 글, 채팅 답변처럼 한국어로 쓰는 글 전부에 적용됩니다. 어떤 글에 어떤 규칙 파일을 쓰는지는 `적용.md` 의 도메인 표에 있고, 규칙 원문은 `rules` 폴더에 있습니다.

이미 쓴 글은 "이 글 NO-AI로 검사해줘"라고 부탁하면 검사 도구로 걸린 규칙을 찾아 줍니다.

## 켜고 끄기

처음에는 켜져 있습니다. 끄려면 `/no-ai:off`, 다시 켜려면 `/no-ai:on` 을 입력합니다.

한 번 끄면 세션을 새로 열어도 꺼진 채로 남고, 그 PC의 모든 세션에 적용됩니다. 세션을 열 때마다 지금 켜져 있는지 꺼져 있는지 한 줄로 보여 줍니다.

꺼 두어도 규칙 사본을 고치지 못하게 막는 기능과 자동 업데이트는 계속 동작합니다.

## 반응으로 규칙을 고치는 과정

NO-AI는 쓰는 사람의 반응을 모으고, 점수를 매기고, 규칙에 넣고, 효과를 재는 일을 되풀이하며 규칙을 고칩니다. 이 순환을 플라이휠이라고 부릅니다. 반응 모으기, 점수 매기기, 효과 재기는 매일 밤 저장소 관리자 PC에서 자동으로 돌고, 규칙에 넣는 일은 관리자가 승인할 때 합니다.

관리자 PC가 잠들어 밤 실행을 건너뛰면, 다음 날 처음 여는 세션이 그 일을 뒤에서 대신 돌립니다. 관리자 PC가 아니면 이 확인은 아무것도 하지 않고 바로 끝납니다.

### 1. 반응 모으기

대화 기록에서 사용자가 답변 바로 다음에 한 말을 읽습니다. "슬롭", "어색", "이상하", "장황", "번역투" 같은 말이 있으면 지적, "좋아", "최고", "마음에 들" 같은 말이 있으면 칭찬으로 셉니다. "좋아 보여?"처럼 물음표가 붙은 말은 칭찬으로 세지 않습니다.

지적이나 칭찬은 바로 앞 답변과 함께 규칙 후보로 남습니다. 그 답변이 어긴 규칙도 검사 도구로 찾아 같이 적습니다.

### 2. 후보에 점수 매기기

후보마다 아래 식으로 점수를 매기고, 점수가 높은 후보부터 검토합니다.

$$
S = b + 2\min(r,\ 2) + \min(k,\ 3)
$$

- $b$: 기본 점수. 지적은 3, 칭찬은 2입니다.
- $r$: 같은 세션에서 앞뒤 3시간 안에 나온 다른 지적 수입니다. 같은 지적이 되풀이되면 앞 지적을 제대로 고치지 못했다는 뜻이라 점수를 가장 많이 더합니다.
- $k$: 이 후보의 답변이 어긴 규칙에 다른 지적의 답변도 걸린 횟수입니다. 지적받은 답변마다 같은 규칙이 걸리면 그 규칙의 문장이 약하다고 봅니다.

지적 하나는 3점에서 10점, 칭찬 하나는 2점에서 9점을 받습니다. 보고서에는 점수마다 어떤 항목으로 더했는지 함께 적어 관리자가 순서를 확인할 수 있습니다.

### 3. 규칙에 넣기

관리자가 "반영"이라고 하면 점수가 높은 후보부터 검토합니다. 기존 규칙과 겹치는 후보는 새 규칙을 만들지 않고 기존 규칙의 문장을 고칩니다. 고친 규칙은 설치한 PC가 다음 요청 때 받아(많아야 5분에 한 번) 그다음 요청부터 씁니다.

### 4. 효과 재기

위반율은 기간 $D$ 동안 쓴 답변 100개 가운데 규칙 $R$ 에 걸린 답변 수입니다.

$$
v_R(D) = 100 \times \frac{H_R(D)}{A(D)}
$$

$A(D)$ 는 기간 안의 한국어 답변 수, $H_R(D)$ 는 그중 규칙 $R$ 에 걸린 답변 수입니다. 규칙을 넣은 날이 $t$ 이면 넣기 전 14일과 넣은 뒤 14일의 위반율을 비교합니다.

$$
\Delta_R = v_R\big([t+1,\ t+15)\big) - v_R\big([t-14,\ t)\big)
$$

$\Delta_R$ 이 0보다 작으면 규칙을 넣은 뒤 위반이 줄었다는 뜻입니다. 줄지 않은 규칙은 문장이나 검사를 고칠 후보로 다시 올라옵니다.

훅은 요청마다 적용.md 를 가리키지만, Claude가 그 파일을 실제로 열었는지는 답변 글만 봐서는 알 수 없습니다. 그래서 날마다 한국어 답변을 한 세션 가운데 그날 적용.md 나 `rules/` 의 규칙 파일을 한 번이라도 직접 읽은 세션의 비율도 잽니다. 보고서에는 최근 14일 치를 둡니다.

위반율이 가장 높은 규칙 2~3개는 요청마다 첫 문장을 Claude에게 따로 강조해 보여 줍니다. 개수 표기 규칙(C49)은 이렇게 보여 준 뒤 위반율이 25~33에서 3~7로 줄었습니다.

### 5. 만족도와 비교 시험

만족도는 한 주 동안의 지적 수 $c$ 와 칭찬 수 $p$ 로 계산합니다.

$$
\text{만족도} = \frac{p}{c + p}
$$

매주 한 번은 같은 요청 14개를 그때의 규칙으로 다시 쓰고, NO-AI 없이 쓴 고정 글과 어느 쪽인지 가린 채 비교합니다. 규칙을 읽은 판정자와 규칙 없이 실무자 눈으로 보는 판정자가 따로 판정합니다. NO-AI 쪽을 선택한 횟수가 줄면 지난주에 넣은 규칙부터 다시 봅니다.

판정자마다 같은 글을 3번 판정하고, 요청마다 2번 이상 고른 쪽을 그 판정자의 답으로 셉니다. 3번이 모두 다르면 비슷함으로 칩니다.

보고서에는 3번이 모두 같았던 요청의 비율을 일치율로 함께 적습니다. 일치율이 낮은 주에는 한두 건 차이를 우연으로 봅니다.

다른 PC의 반응은 대화 원문 없이 아래 사용 통계의 숫자로만 받습니다.

## 사용 통계

NO-AI가 켜져 있으면 하루 한 번 숫자 통계를 보냅니다. 위의 위반율과 만족도를 계산하는 데 쓰고, 처음 안내가 나온 다음 날부터 보냅니다. 보내는 값은 날짜별 답변 수, 규칙별로 걸린 답변 수, 글에 대한 지적 수와 칭찬 수, 익명 번호, 규칙 버전입니다.

대화 내용, 파일 경로, 프로젝트와 세션 이름은 보내지 않습니다. 지적과 칭찬은 "어색해", "좋아" 같은 말이 들어간 반응을 내 PC에서 세고 숫자만 보냅니다.

보내지 않으려면 사용자 폴더의 `.claude` 안에 `.no-ai-nostats` 파일을 만듭니다. `/no-ai:off` 로 꺼 둔 동안에도 보내지 않습니다.

## 업데이트 받기

따로 할 일은 없습니다. 켜 둔 상태에서 요청을 보내면 많아야 5분에 한 번 뒤에서 새 규칙을 받고, 그다음 요청부터 적용됩니다. 쓰고 있던 세션을 껐다 켤 필요가 없습니다.

훅이나 명령처럼 플러그인 자체가 바뀐 경우는 6시간에 한 번 받고, 다음에 Claude Code를 켤 때 적용됩니다. 지금 바로 받으려면 터미널에서 `claude plugin marketplace update no-ai` 와 `claude plugin update no-ai@no-ai` 를 차례로 실행하고 Claude Code를 다시 엽니다. 이 두 명령이 실패하면 `claude plugin marketplace remove no-ai` 를 실행한 뒤 설치의 1번과 2번을 다시 합니다.

## 규칙 제안

쓰다가 규칙에 없던 AI 말투를 찾았거나 규칙끼리 겹치는 곳을 보면 Claude에게 "이 표현 NO-AI 규칙으로 제안해줘"라고 말합니다.

Claude가 기존 규칙과 겹치는지 보고, 겹치면 기존 규칙을 고치는 쪽으로 제안을 정리합니다. 바뀌는 내용을 보여 주고 허락을 받은 뒤 내 GitHub 계정으로 제안을 올리고 링크를 줍니다.

링크를 열어 Create pull request 를 누르면 끝납니다. 요청 원문, 고객사, 동료 이름, 파일 내용은 제안에 넣지 않습니다.

처음 한 번은 터미널에서 `gh auth login` 으로 GitHub에 로그인해 둡니다. 저장소 관리자가 제안을 합치면 설치한 사람 모두에게 업데이트로 갑니다.

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| 세션을 열어도 "NO-AI가 켜져 있습니다"가 안 보이거나 `/no-ai:off` 가 없는 명령이라고 나옵니다 | 설치 뒤 다시 열지 않았습니다. Claude Code를 다시 엽니다. `/reload-plugins` 로 불러온 창에서는 이 문구가 나오지 않을 수 있지만 명령 목록에 `/no-ai:off` 가 보이면 설치된 상태입니다 |
| `marketplace add` 가 실패합니다 | git이 없거나 인터넷이 막혀 있습니다. 터미널에서 `git --version` 을 확인합니다 |
| 설치가 안 됩니다 | 두 명령을 한 번에 붙여 넣었을 수 있습니다. 한 줄씩 따로 실행합니다 |
| 다시 열어도 켜짐 문구가 안 보이거나 답변에 규칙이 적용되지 않습니다 | `python` 명령이 없으면 훅이 돌지 않습니다. 준비의 Python 항목을 확인합니다 |
| "NO-AI가 꺼져 있습니다"가 보입니다 | 예전에 끈 기록이 남아 있습니다. `/no-ai:on` 을 입력합니다 |
| 새 규칙이 들어오지 않습니다 | 마지막으로 받은 지 5분이 안 됐거나 git이 저장소에 닿지 못했습니다. 사용자 폴더의 `.claude/no-ai-live` 폴더와 `.claude/.no-ai-pulled` 파일을 지우면 다음 요청 때 새로 받고, 그다음 요청부터 적용됩니다 |
| "설치된 플러그인 사본이라 고치지 않습니다"가 나옵니다 | 설치된 규칙 파일은 고칠 수 없습니다. 규칙 제안으로 올립니다 |
| "자동으로 받아 온 규칙 사본이라 고치지 않습니다"가 나옵니다 | 5분마다 새로 받는 규칙 사본이라 고쳐도 사라집니다. 규칙 제안으로 올립니다 |

## 지우기

`claude plugin uninstall no-ai@no-ai` 와 `claude plugin marketplace remove no-ai` 를 차례로 실행합니다. 사용자 폴더의 `.claude` 안에 남는 `no-ai-live`, `no-ai-usage` 폴더와 `.no-ai-off`, `.no-ai-nostats`, `.no-ai-pulled`, `.no-ai-updated` 파일도 지웁니다.
