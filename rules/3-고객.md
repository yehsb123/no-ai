# 고객에게 가는 글

## G01 받는 사람 쪽에서 쓰기

    고객에게 주는 문서에 "우리", "사내", "참고용", 내부 조직 약어
    사내 원칙을 고객 화면의 약속 문장으로 옮기기 (FDE 3원칙을 사이트 표로, "이건 고객이 볼 거니까 고객이 원하는 느낌으로 해야 해")
    외부 자료 끝에 우리 쪽 "다음 단계" 목록
    내부 기한을 대외 문서에 옮기면서 약속처럼 쓰기
    확정 안 된 금액이나 조건을 먼저 적기
    예시 화면 면책 문구가 회사 소개나 특허 같은 사실 진술까지 덮게 두기
    복사해 쓰는 명령 예시에 아직 없는 기능 넣기
    오늘 새로 만든 기능을 원래 있던 기능처럼 적기
    만드는 중인 기능을 "없습니다" 로만 적기, 또는 "준비 중" 으로 덮기
    새 판 문서에 이전 판과 바뀐 점을 장으로 넣기 ("1.0에서 바뀐 점은 없어도 될 듯?")
    담당 칸에 직원 이름 적기 (담당은 회사 이름, "담당은 그냥 하이퍼이지라고만 해")

고객 문서는 받는 사람이 할 행동으로 쓴다. 내부 규칙을 적을 때는 "내부 규칙, 대외 약속 아님"을 붙인다.

명령 예시에 준비 중인 기능을 넣으려면 줄마다 버전을 표시한다. 준비 중인 기능은 지금 되는 부분과 만드는 중인 부분을 같이 적는다 ("알림을 만들고 있습니다. 지금은 커뮤니티를 열어 봐야 알 수 있습니다").

고객에게 넘기는 인수인계 문서는 받아서 운영할 사람의 관점으로 쓴다.

검사: 줄 `참고용|사내 전용`

## G02 원문 그대로 옮기기

고객이나 현업이 보낸 요구사항, 결함 신고, 회의 발언은 원문 그대로 옮긴다. 다듬거나 항목으로 쪼개지 않는다. 해석이 필요하면 원문 아래에 따로 적는다.

## G03 메일 형식

    붙여 넣을 메일에 마크다운 표 쓰기 (메일 프로그램에서 깨진다)
    첨부에 있는 내용을 본문에 다시 나열하기
    [ 작성 완료 항목 ] 같은 대괄호 소제목 달기

표를 쓸지는 붙여 넣을 곳을 보고 정한다. 내용 길이는 기준이 아니다.

메일에는 "- 사업본부 : 3.첨단"처럼 줄로 적거나 문장으로 쓴다. 첨부가 있으면 본문에는 첨부에 없는 정보와 질문만 남기고, 소제목 대신 문단과 번호로 나눈다.

검사: 줄 `^\s*\|.*\|\s*$|^\s*\[ .+ \]\s*$`

## G04 메일 질문

    같은 화면에서 나오는 값을 따로따로 묻기
    고객이 답할 질문과 내부에서 정할 질문을 한 메일에 섞기

질문은 아는 배경을 먼저 적고 확인만 청한다. "소스를 SVN에 올려야 하는지 확인 부탁드립니다" 대신 "이전 건도 등록과 계정 발급까지만 진행했다고 알고 있습니다. 이번에도 같게 진행하면 되는지 확인 부탁드립니다"로 쓴다. 예, 아니오로 답할 수 있어 왕복이 한 번 줄어든다.

## G05 요청은 요청으로

상대에게 작업을 부탁하는 메일을 "역할 분담 안내"로 감싸거나 선을 긋는 글로 쓰지 않는다. 받는 사람이 해 줄 일을 요청으로 쓴다.

부탁하는 메일은 첫 문단에 부탁할 내용을 바로 쓴다. "써 보시기를 권해 드리려고"처럼 권하는 말투 대신 여쭙는 말투로 쓴다 ("뭔가 겸손하고 좀 더 명확하게 해보고 싶어").

의견을 청할 때 우리 서비스를 낮추지 않는다. "아직 부족한 점이 많아" 대신 "정식 출시를 앞두고 현장에서 바로 쓸 수 있는 상품으로 완성하기 위해"처럼 완성을 향한다고 쓴다 ("부족한 점이 많다기보단 정말 완벽한 런칭을 할 거다").

받는 쪽이 고객이 아니라 조언해 줄 사람이면 써 달라고 청하지 않고 의견만 청한다. 받는 대상이 다르면 문안도 나눈다 ("OTA한텐 써 달라기보단 피드백을 달라는 느낌").

## G06 고객 문구의 결

대기업 고객에게는 잘 관리되고 있고 다음 단계까지 준비되어 있다는 인상을 준다.

- 진행 보고에 그치지 않고 고객이 궁금해할 내용을 먼저 안내한다
- 지금 하는 작업을 분명히 말하고 다음 산출물과 후속 작업까지 적는다
- 확정 전 내용은 "확정되는 대로", "이를 기준으로", "후속으로"로 쓴다
- "혹시 궁금하실까 하여", "먼저 공유드립니다" 같은 표현을 자연스럽게 쓴다
- 내부 사정을 변명처럼 쓰지 않는다
- 정중하고 안정감 있는 문체로 두세 문장에서 네 문장

사람이 직접 쓴 메일이 기준이다. "안녕하십니까 책임님 (회사) (이름)입니다. 받은 제품정보 전체 확인완료하였습니다. 보내주신 수정사항이 어떤제품에 어떤설명이 어떻게 바뀌었는지 한번 알려주시면 감사할것같습니다." 인사, 받은 내용 확인 한 줄, 요청 한 줄로 끝난다.

## G07 고객 양식과 일정표

고객이 준 양식에 채우는 문서는 받은 양식의 줄, 번호, 칸, 비고를 그대로 두고 우리 내용만 채운다. 끼워 넣은 줄에는 "추가"를 붙인다. 양식을 읽지 못하면 다른 틀로 만들지 않고 먼저 양식을 다시 받는다 ("내가 공유한 거 있잖아, 그거에 기반해서 써 달라는 건데").

고객에게 내는 일정표(WBS)는 대분류 수준으로 짠다. 작은 작업은 대분류 한 줄에 묶고, 이슈와 리스크 문구는 넣지 않는다 ("너가 짠 건 너무 디테일한 거 같아서"). 산출물 칸에는 고객이 받기로 한 산출물만 적는다 ("산출물 최대한 빼라니까").
